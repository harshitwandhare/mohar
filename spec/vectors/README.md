# Test vectors

The format these vectors check is described in [`../receipts-v1.md`](../receipts-v1.md), which also
defines the conformance levels.

`v1.json` is generated by the Rust implementation from a fixed, test-only seed (bytes `0x00` to `0x1f`)
and checked byte for byte by `crates/mohar-core/tests/vectors.rs`. It holds the public key, three
receipts with their canonical bytes, SHA-256 hashes and signatures, and a checkpoint over them.

To check another implementation, rebuild each receipt from its fields and compare:

1. the RFC 8785 canonical bytes of the receipt with `sig` included equal `canonical_hex`;
2. the SHA-256 of those bytes, prefixed `sha256:`, equals `sha256`, and the next receipt's `prev`;
3. the Ed25519 signature in `sig` verifies against `public_key` over the canonical bytes without `sig`;
4. the checkpoint's `head` is the last receipt's hash, and its signature verifies the same way.

`check.py` does exactly this in Python, independently of the Rust code:

```bash
pip install cryptography
python spec/vectors/check.py spec/vectors/v1.json
```

## Conformance

`conformance-v1.json` holds seventeen small logs, each with the conformance level a verifier must report:
one that reaches Level 2, seven that stop at Level 1 and nine that reach no level. Each case gives the key
in the log directory (`log_key`), the key the verifier was given some other way (`pinned_key`, or null)
and the checkpoints published outside the machine. `crates/mohar-core/tests/conformance.rs` builds the
file from two fixed seeds and checks every case with the Rust verifier; `check.py` writes each case out as
a log directory, reads it back and must reach the same level.

```bash
python spec/vectors/check.py spec/vectors/conformance-v1.json
```

The same checker reports the level of a real log:

```bash
python spec/vectors/check.py --log .mohar --pinned-key owner.key --checkpoints published.jsonl
```

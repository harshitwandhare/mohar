Trust, earned.

Mohar watches what an AI agent does, checks whether the result was right, and turns that record into permission, one capability at a time. One wrong move on a gated capability and the right is gone. Every decision is sealed with a receipt.

A simulation of Mohar's rules in your browser. Each task is checked by tests, never by the agent's opinion of itself. Receipts form a real SHA-256 chain; the browser demo has no keys, so it doesn't sign them.

    Four rules, kept in code

    Record
    Every action goes into a local hash-chained log, signed with the agent's key.
    Verify
    Tests, diffs, replays or a person accepting the work decide the outcome. A model grading itself never counts.
    Score each capability
    Editing docs and running migrations are tracked apart. Hard gates sit outside the score, so an average can't hide a failure.
    Decide
    Inside earned limits the action runs. Outside them it goes to the right person, with the agent's history attached.

    What a receipt proves

    {
  "v": 1,
  "seq": 4182,
  "prev": "sha256:9f2c…e01a",
  "ts": "2026-11-03T14:22:07.311Z",
  "agent": { "id": "agent:claude-code/laptop/7c1e",
             "key": "ed25519:Mx3f…Q" },
  "authority": [{ "principal": "human:7f3a09c2",
                  "granted": ["fs.edit.*"] }],
  "action": { "capability": "fs.edit.tests",
              "args_sha256": "c41b…77d0" },
  "decision": { "result": "allow", "level": 1,
                "wilson_lower": 0.83, "n": 14 },
  "verification": { "kind": "tests", "result": "pass" },
  "sig": "ed25519:8sQ1…wA"
}
    prev
    The hash of the receipt before this one. Change or delete any receipt and every later one stops matching.
    authority
    The chain of people and agents that handed this agent its rights, by pseudonymous ID so the log holds no names. Each link can only narrow what it received.
    args_sha256
    The exact action. A person's approval is bound to this hash, so a different action can't run under it.
    decision
    Why it ran: the level on this capability, and the evidence behind it.
    sig
    Ed25519 over the RFC 8785 canonical bytes, made by a daemon key the agent never sees.

    An example of the planned format. The full field list is in the design.

    How trust moves

    LevelWhat happensTo get here
    Ask firstEvery action goes to a person.The start, and where any gate violation or high-risk failure sends an agent.
    SupervisedLow-risk reversible actions run; 20% are sampled for review.10 verified outcomes, a lower 95% Wilson bound of 0.80, and 7 days at the level below.
    TrustedActions run inside the capability's gates; 5% are sampled.30 verified outcomes and a lower bound of 0.95. Never for high-risk irreversible capabilities.

    Five successes out of five give a lower bound of about 0.57, so a lucky streak promotes nobody. Evidence fades with a 30-day half-life. Demotion is immediate; promotion always waits. These are starting values for the benchmark to test. Read the full design

    Built to sit beside what you run

    Mohar works with the orchestrators, identity providers and policy engines you already run. It's planned to plug into Claude Code hooks, MCP servers, awslabs/cli-agent-orchestrator, Google ADK, Microsoft's Agent Governance Toolkit and Paperclip.

    It's early and built in the open. The signed receipt log is the first piece being written, and nothing is production-ready yet.

# Governance

## Who decides

Mohar has one maintainer today, [@harshitwandhare](https://github.com/harshitwandhare), who reviews and
merges every change and makes final calls on design and releases.

## How changes are made

1. Every change starts as an issue with "Done when" criteria.
2. A pull request links that issue. A check fails pull requests that don't.
3. CI must pass, and the maintainer reviews every pull request. Nothing merges unreviewed.
4. Design changes update `docs/design.md` in the same pull request.

## Becoming a maintainer

Contributors who land several substantial, well-tested changes and review others' work carefully may be
invited to become maintainers. As that happens this file will describe how decisions are shared.
